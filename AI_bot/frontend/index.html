Adding the chatbot to the game

The narrator chatbot helps players who are stuck on a mission. It runs as a separate backend service. Your page needs one script, one stylesheet and two requests. This page is also a working demo: chat.js and chat.css here are the files to copy.

Overview

Player's browser (chat.js)  --2 JSON requests-->  Chatbot backend  -->  AI model
                                                   holds the API key,
                                                   the answers and the hints

The browser never receives answers or hints. The chatbot hands out hints one at a time, in its own words. The game itself, not the chatbot, decides whether an answer is correct.

Quick start

  1. Copy chat.css and chat.js into your project.
  2. Include them on the page that shows missions: 
    <link rel="stylesheet" href="chat.css">
<script src="chat.js"></script>
  3. Initialise once, with the address of the chatbot backend (no trailing slash): 
    AradBot.init({ apiBase: "https://YOUR-BACKEND/api/bot" });
  4. Tell the widget which mission is on screen. A "Ajutor" button appears; the chat opens when the player taps it: 
    AradBot.setMission("primaria");   // when a mission screen opens
AradBot.clearMission();           // when the player leaves it

JavaScript API

CallWhat it does
AradBot.init(options)Call once. Options: apiBase (string) and useMock (boolean, fake replies with no backend).
AradBot.setMission(id)Shows the button for that mission. Changing to a different id clears the chat and starts a new session. Calling it again with the same id does nothing.
AradBot.clearMission()Hides the button and the chat and ends the session.
AradBot.open() / close()Open or close the chat from your own code.

Backend API

chat.js makes these calls for you. They are listed here for anyone testing the backend directly.

POST {apiBase}/start: begins a chat for one mission.

request   {"mission_id": "primaria"}
200       {"session_id": "9b2f…", "title": "Primăria"}
404       unknown mission id

POST {apiBase}/chat: sends one player message.

request   {"session_id": "9b2f…", "message": "Mă ajuți?"}      (1 to 500 characters)
200       {"reply": "Ridică privirea…"}
404       session not found: start a new session
422       invalid body (empty or too long message)
429       too many messages: ask the player to wait
5xx       show a generic error

A reply can take several seconds, so the widget shows a waiting bubble and disables the send button meanwhile.

Behaviour to expect

  • Players can ask for hints as often as they like, in their own words. The bot decides when to give one, and goes from vague to more direct.
  • Replies are plain text of roughly 30 to 100 words, in Romanian or English, matching the player.
  • If a player types an answer into the chat, the bot sends them to the answer field and never says whether it is right. The bot's wording comes from the ANSWER_BOX setting on the backend: keep it identical to the label of your answer field.
  • Leaving a mission ends the chat. Coming back starts a fresh one.

Rules for the frontend

  • Never put the AI provider key, answers or hints in frontend code.
  • Show replies with textContent, never innerHTML. chat.js already does this.
  • The backend only accepts requests from origins it allows (CORS). Send the backend developer the exact origin of your site, for example https://arad-quest.example.
  • Use HTTPS in production.
  • Answer checking stays in the game backend. Do not ask the chatbot whether an answer is correct.

Customising

  • Text: every string the player sees is in the TEXT object at the top of chat.js (Romanian by default).
  • Colours: change --aq-accent, --aq-bg and --aq-text on .aq-bot in chat.css.
  • Layout: the main classes are .aq-bot__launcher, .aq-bot__panel, .aq-bot__log, .aq-msg--bot and .aq-msg--user.

Try it

Serve this folder over HTTP, for example python -m http.server 5500, and open http://localhost:5500. For a real backend, ask its developer to allow that origin. Mock mode needs no backend.
